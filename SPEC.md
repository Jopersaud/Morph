# Morph — Local File Converter for macOS

**Build spec for Claude Code** · v1.0 · Open source (MIT)

> **Scope: personal, local use.** The source is hosted on GitHub, but v1 is built from source and installed on the owner's own Mac. It isn't signed for distribution, notarized, or packaged for anyone else. That can be added later without changing the architecture.

---

## 1. What we're building

A native macOS app that turns a file into a closely related format (HEIC → JPG, MOV → MP4, DOCX → PDF, WAV → MP3) **entirely on the device**. There are no uploads, no accounts, and no network calls. The converted file is saved **next to the original**, so the user never needs to open another app or pick a save location.

It's inspired by Tangerine (tangerineformac.com), but it's free, open source, and built around the Finder.

### Core user story

> I right-click a file (or several) in Finder → **Convert to ▸ PNG**. A second later, `photo.png` appears beside `photo.heic`. I never left Finder.

### Goals

1. **Local only.** No network entitlements, no telemetry, no update pings unless the user turns them on.
2. **No friction.** Conversion takes one or two clicks from Finder. Output goes beside the source automatically.
3. **Native first.** Use Apple frameworks (ImageIO, AVFoundation, PDFKit, AppKit text system) wherever they can do the job. Bundle open-source libraries only to fill gaps.
4. **Batch-friendly.** Select 200 files, convert them all, and see progress. Cancelling is safe.
5. **Hackable.** Adding a new conversion means writing one Swift type and registering it.

### Non-goals (v1)

- Cloud sync, accounts, or any server component
- Full editing (cropping, trimming, and merging come later; see §12)
- Publishing of any kind: no notarization, DMG, Homebrew cask, Mac App Store, or auto-updates. A paid Apple Developer account must **not** be required.
- Windows or Linux

## 3. Ways to convert (entry points)

All entry points feed the same `ConversionService`.

| # | Entry point | Priority | Behavior |
|---|---|---|---|
| E1 | **Finder right-click submenu** (Finder Sync extension) | P0 | `Convert to ▸` submenu listing the valid targets for the selected files (the intersection when several files are selected). Picking one converts immediately using the default options. The last item, `More Options…`, opens the options panel. |
| E2 | **Services / Quick Action** (`NSServices`) | P0 | `Convert with Morph…` appears under Services/Quick Actions. It opens the compact **Picker panel** (below). This is the fallback when the Finder Sync extension is disabled. |
| E3 | **Main window drop zone** | P0 | Drag files onto the window, or click to choose files. Target format buttons appear, and a click converts. |
| E4 | **Menu bar extra** | P1 | Drop files onto the menu bar icon to get the Picker panel. The menu also shows recent jobs and progress. |
| E5 | **Dock icon drop / Open With** | P1 | Dropping files on the Dock icon, or choosing Open With → Morph, opens the Picker panel. |
| E6 | **Shortcuts (App Intents)** | P1 | `Convert Files` intent with parameters files, target format, and options. Makes Morph scriptable from Shortcuts and Automator. |
| E7 | **CLI** (`morph`) | P2 | `morph convert *.heic --to jpg --quality 85`. It uses the same core package, so it's handy for testing and power users. |
| E8 | **Modifier-drag shelf** | P3 | Optional Tangerine-style mode: hold ⇧ while dragging files anywhere and a floating shelf of target formats appears. Needs Accessibility permission, so it's off by default. |

### Picker panel (used by E2, E4, E5)

- A small floating `NSPanel` near the cursor.
- A grid of target format chips, grouped by category, with the most-used formats first.
- Keyboard-first: type to filter (`pn` → PNG), ↑↓←→ to move, ⏎ to convert, ⌥⏎ to open options, Esc to close.
- Shows the source summary, for example "3 images · 12.4 MB".

## 4. Output behavior

- **Location:** same folder as the source.
- **Name:** `name.ext` becomes `name.<newext>`. On a name collision, use `name (1).<newext>`, `name (2).<newext>`, and so on. Never overwrite silently.
- **Original file:** kept by default. A setting offers *Move original to Trash after a successful conversion* (Trash only, never a permanent delete).
- **Metadata:** keep EXIF, GPS, and creation dates where the format supports them. The *Strip metadata* setting removes location and camera data.
- **File dates:** a setting controls whether the output copies the source's creation and modification dates.
- **Atomic writes:** write to a temp file in the same folder (`.name.morph-tmp`), then rename. If the job fails or is cancelled, delete the temp file.
- **Read-only folders:** if the source folder isn't writable, show a single prompt: *Save to…* (remember the choice for this job) or *Skip*.
- **Finish:** show a subtle system notification ("Converted 12 files"). Clicking it reveals the output in Finder. The notification can be turned off.

## 5. Conversion matrix (v1)

"Adjacent" means it's reasonable to convert without the user needing an editor. The engine column says which backend to try first (see §6).

### Images

| From | To | Engine |
|---|---|---|
| HEIC, JPG, PNG, TIFF, BMP, GIF (first frame), WebP, AVIF | JPG, PNG, HEIC, TIFF, BMP, WebP, AVIF, PDF | ImageIO → libwebp / libavif for encoders ImageIO lacks |
| SVG | PNG, JPG, PDF | resvg |
| Any image (multiple selected) | Single multi-page PDF (`Combine into PDF`) | PDFKit |

Options: quality (lossy formats), max long edge (resize), keep/strip metadata, background color when flattening transparency to JPG.

### Audio

| From | To | Engine |
|---|---|---|
| WAV, AIFF, M4A/AAC, MP3, FLAC, ALAC, OGG, Opus, WMA | MP3, M4A (AAC), WAV, AIFF, FLAC, ALAC, OGG, Opus | AVFoundation for Apple formats, FFmpeg for the rest |
| Any video | MP3, M4A, WAV (audio extraction) | AVFoundation → FFmpeg |

Options: bitrate or quality preset, sample rate, mono/stereo.

### Video

| From | To | Engine |
|---|---|---|
| MOV, MP4, M4V, MKV, WebM, AVI, WMV | MP4 (H.264 / HEVC), MOV, WebM (VP9), MKV | AVFoundation (`AVAssetExportSession` / `AVAssetWriter`) → FFmpeg with **VideoToolbox** hardware encoders |
| Any video | GIF (with optional max width and fps) | FFmpeg (palette-gen two-pass) |

Options: preset (Small / Balanced / High Quality / Same as Source), resolution cap, codec, strip audio.

### Documents

| From | To | Engine | Notes |
|---|---|---|---|
| DOCX, DOC, RTF, ODT, HTML, TXT, MD | PDF | `NSAttributedString` + CoreText pagination | MD is parsed via `AttributedString(markdown:)` |
| DOCX, DOC, RTF, ODT, HTML | DOCX, RTF, ODT, TXT, HTML | `NSAttributedString` document types | |
| PDF | PNG, JPG (one file per page, or a folder when there are more than 1 page) | PDFKit | |
| PDF | TXT | PDFKit text extraction | |
| PDF | DOCX | PDFKit text → `NSAttributedString` | **Label as "text only"** in the UI. Layout isn't preserved |
| SRT ↔ VTT, SRT/VTT → TXT | | Pure Swift parser | |
| CSV ↔ TSV, CSV/TSV → JSON, JSON (array of flat objects) → CSV | | Pure Swift | |

### Archives

| From | To | Engine |
|---|---|---|
| Files/folders | ZIP, TAR.GZ | libarchive |
| ZIP, TAR, TAR.GZ, 7Z, RAR | Extract to a folder beside the archive | libarchive (**RAR is extract-only**) |

## 6. Architecture

```
Morph/
├─ project.yml                 # XcodeGen
├─ Apps/
│  ├─ MorphApp/                 # SwiftUI app, menu bar extra, Picker panel, Settings
│  ├─ MorphFinderSync/          # Finder Sync extension (sandboxed, thin)
│  └─ morph-cli/                # CLI target (swift-argument-parser)
├─ Packages/
│  ├─ ConversionKit/           # Core: protocols, registry, job queue, naming, options
│  ├─ Engines/

│  │  ├─ MediaEngine/          # AVFoundation + FFmpeg wrapper
│  │  ├─ DocumentEngine/       # PDFKit, NSAttributedString, subtitles, CSV/JSON
│  │  └─ ArchiveEngine/        # libarchive
│  └─ MorphIntents/             # App Intents
├─ Vendor/                     # Build scripts + prebuilt xcframeworks (not source dumps)
│  └─ scripts/build-ffmpeg.sh …
├─ Tests/Fixtures/             # Small sample files per format (< 200 KB each)
└─ docs/
```

### Core types (ConversionKit)

```swift
public struct FileFormat: Hashable, Sendable {
    public let id: String            // "png"
    public let displayName: String   // "PNG"
    public let utType: UTType
    public let category: Category    // .image, .audio, .video, .document, .archive
    public let preferredExtension: String
}

public protocol Converter: Sendable {
    static var id: String { get }
    /// Input formats this converter accepts, with the targets it can produce from each.
    static var routes: [FileFormat: [FileFormat]] { get }
    static func isAvailable() -> Bool          // e.g. runtime ImageIO capability check
    func convert(_ job: ConversionJob,
                 progress: @Sendable (Double) -> Void) async throws -> URL
}

public struct ConversionJob: Sendable {
    public let source: URL
    public let target: FileFormat
    public let options: ConversionOptions     // typed per category; defaults from Settings
    public let destination: URL               // resolved by OutputPlanner
}
```

- **`ConverterRegistry`**: gathers every converter's `routes`. For a given `UTType` it returns the ordered target list, and for a (source, target) pair it returns the best available converter. **Priority order is native engine, then bundled library.**
- **Format detection**: identify the source by content (`UTType` from the resource values, with a magic-byte sniff as fallback), never by extension alone.
- **`OutputPlanner`**: handles naming, collisions, temp paths, and the writable-folder check (§4).
- **`JobQueue`**: an actor. Concurrency defaults to `activeProcessorCount - 2` for images and documents, and **1–2** for video (the hardware encoder is the bottleneck). It supports cancel-all, per-job cancel, and progress aggregation, and exposes an `AsyncStream<JobEvent>` for the UI.
- **Errors**: a typed `ConversionError` (`unsupported`, `unreadable`, `encoderUnavailable`, `diskFull`, `cancelled`, `engine(String)`) with human-readable messages. One bad file never stops the rest of a batch.

### Finder Sync ↔ app communication

The Finder Sync extension **must** be sandboxed, so it does no conversion itself.

1. The extension watches `/` (all volumes) and builds the `Convert to ▸` menu by asking the registry for targets. It links ConversionKit's registry only, not the engines.
2. On click, it sends the selected file paths and the target to the main app via a custom URL scheme (`morph://convert?target=png&path=…`, opened with `NSWorkspace`). **Don't** depend on App Groups or XPC Mach services: they need entitlements a free Personal Team may not provide. For very large selections, the extension writes the path list to a temp file and passes only that file's path.
3. The main app is non-sandboxed with Hardened Runtime. It launches as a background agent if needed (no Dock icon while it's only doing a background job), runs the jobs, and posts a notification.

### FFmpeg integration

- Build **LGPL-only** FFmpeg as dynamic `xcframework`s: no `--enable-gpl`, no x264/x265. Use VideoToolbox for H.264/HEVC encoding and libvpx for VP9, libopus, libvorbis, libmp3lame, and FLAC (built in).
- Call it through the libav* C APIs from a thin Swift wrapper. **Don't** shell out to an `ffmpeg` binary.
- Provide a reproducible build in `Vendor/scripts/build-ffmpeg.sh`, and cache the output in CI.

## 7. Security, privacy, sandboxing

- **No network code paths.** CI runs a check that fails the build if `URLSession`, `NWConnection`, `CFNetwork`, or socket APIs appear anywhere in the app's code.
- **Updates:** none built in. To update, run `git pull && make install`.
- **Main app:** **not sandboxed**, signed with the Personal Team or ad-hoc. This is needed to write beside arbitrary source files without asking for folder access every time.
- **Finder extension:** sandboxed, as Apple requires.
- **Temp files:** created in the destination folder (for atomic rename) or in `FileManager.temporaryDirectory`, and cleaned up on launch.
- **No analytics or crash reporting SDKs.** Crash logs stay in macOS's own diagnostics.
- The README must state all of this in plain language.

## 9. UI

### Main window (small, about 520×420)

- A large drop zone ("Drop files to convert"), plus a *Choose Files…* button.
- After files are dropped: a source summary and target chips. Chips that aren't valid for every selected file are disabled, with a tooltip explaining why.
- A gear next to each chip opens the options popover for that target.
- Below the drop zone: a **Jobs list** with filename, arrow, target, a progress bar, and then either Reveal / Retry or the error.

### Settings (SwiftUI `Settings` scene)

- **General:** launch at login, show in menu bar, show Dock icon, notifications on/off.
- **Output:** collision naming style, trash original, keep dates, strip metadata, default "Save to…" behavior for read-only folders.
- **Formats:** per-category defaults (JPG quality, video preset, audio bitrate…). Choose which targets appear in the Finder submenu and in what order, and hide ones you never use.
- **Finder:** status of the Finder extension, with a button that opens *System Settings → Login Items & Extensions*.
- **Advanced:** concurrency limit, reveal logs.

### Onboarding (first launch, 2 screens max)

1. What Morph does, plus the promise that "everything stays on your Mac".
2. Enable the Finder extension, with a deep-link button and live status.

### Look and feel

System materials, SF Symbols, full support for light and dark mode, VoiceOver labels on every control, full keyboard navigation.

## 11. Testing and CI

- **Unit tests** for each converter route: convert a fixture, then assert the output exists, `UTType` detection agrees with the target, dimensions/duration/page count match the expected values, and the file opens with the native reader (ImageIO / AVAsset / PDFDocument).
- **Registry tests:** every advertised route has at least one fixture test. CI fails if a route has no test.
- **OutputPlanner tests:** collisions, unicode names, read-only folders, names with no extension, files in iCloud Drive that are "not downloaded" (trigger a download or skip with a message).
- **Cancellation tests:** a cancelled job leaves no temp or partial files behind.
- **Network guard:** the lint step from §7.
- **UI smoke test:** launch, drop a fixture, convert, and assert the job completes.
- **CI pipeline:** build the vendor libraries (cached), build the app with code signing disabled, and run the tests. No release or signing steps.

## 13. Local install (no paid Apple account)

`make install` must:

1. Run `xcodegen`, then `xcodebuild -configuration Release`, signing with the team in `Local.xcconfig`. That file is git-ignored and holds `DEVELOPMENT_TEAM`. If it's empty, fall back to ad-hoc signing.
2. Copy `Morph.app` to `/Applications`, replacing any old copy, and register the Finder extension with `pluginkit -e use -i <extension bundle id>`.
3. Print the next steps: open Morph once, then enable the extension in **System Settings → General → Login Items & Extensions → Finder** if it isn't already on.

Also provide `make uninstall`, which removes the app, the CLI link, and the extension registration.

The README should have a short "Build it yourself" section: install Xcode, `brew install xcodegen`, (optionally) add your free Apple ID in Xcode → Settings → Accounts and put its team ID in `Local.xcconfig`, then run `make install`.

If the Finder extension won't load with ad-hoc signing, say so in the README and recommend the free Personal Team. The Services menu, drop zone, and menu bar entry points must still work without it.
